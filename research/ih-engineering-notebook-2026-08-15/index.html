VPD on memorize-saturated transformers

  • 1L fails month recall
  • 4L, 8L see analysis below.

There is a wrinkle: on the fried transformer, a future looking CI can reconstruct perfectly, while a causal CI is destroyed.

  • Maybe this makes sense: if the CI can’t see the future, then it would have to figure out the answer to the question before letting the model compute it
  • If it already knew the answer, it just has to figure out which circuits to turn on to make the model do what it wants
  • This effect doesn’t really show up in the pile-4L(paper) model, perhaps since the fact recall tokens are so rare the CI-Net chooses to not deal with them, and tank the cost.

This is a strange choice, since the paper doesn’t mention it, but is reflected in the code.

Fried transformer: model trained to memorize dataset, available in different epoch, head #, layer # configs. I stick with H = 6, variable layer, and epochs go until memorization achieved.

  • Data isn’t perfect, some people map to different birthdays, model doesn’t actually fully memorize everyone, there are a few stragglers. Work around this by cutting out the stragglers. I should be careful about this tomorrow, and figure out what caused the stragglers and if the stragglers are the same across all the models.

Can we let the model decide what rank matrices it wants? - VPD seems to do this already since any rank 2 matrix can be represented as the sum of 2 rank 1, and matrix multiplication is distributive.

VPD seems to lose the ability to add “frenchness” to the token, but is able to recognize that it should be a place.

Deeper depths seem more conducive to being broken down by VPD.

Misc notes: two shot prompting is required for OPT to retrieve capital-> country, pile(paper) does not seem to store this kind of fact. This applies to weekday recall as well. “The day after Monday is Tuesday. The day after Tuesday is”
